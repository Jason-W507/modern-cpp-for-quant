# Event-driven backtest teaching project

This C++20 project is the final, independently buildable snapshot from
*Python 量化人的 Modern C++*. It demonstrates an auditable single-symbol event
flow rather than a production trading platform:

```text
CSV -> MarketEvent -> Strategy -> OrderIntent -> Fill -> Portfolio -> Summary
```

`MarketEvent`, `OrderIntent`, and `Fill` are validated value objects rather
than public aggregates with invalid defaults. The portfolio is explicitly a
cash account: initial cash must be finite and positive, purchases cannot exceed
cash, and sales cannot exceed holdings. CSV failures retain line, field, and
error-code data; the CLI renders that structured result separately.

## Reproduce it

From the repository root on Linux or WSL:

```bash
cmake -S project -B build/ch17 -DCMAKE_BUILD_TYPE=Release
cmake --build build/ch17 -j
ctest --test-dir build/ch17 --output-on-failure
./build/ch17/quant_backtest project/data/sample.csv
./build/ch17/quant_backtest project/data/sample.csv 1.0 10.0
```

The default and configured-cost runs have exact output contracts:

```text
backtest-ok events=3 fills=1 cash=7525.000 equity=10100.000 return=1.000000% max-drawdown=0.000000% volatility=0.002880 fee-per-fill=0.000 slippage-bps=0.000
backtest-ok events=3 fills=1 cash=7521.525 equity=10096.525 return=0.965250% max-drawdown=0.034750% volatility=0.003081 fee-per-fill=1.000 slippage-bps=10.000
```

Eleven CTest cases protect four public behavior seams, the two CLI summaries,
invalid configuration, the multi-asset valuation boundary, a correctness-gated
benchmark, and its isolated failure fixture. The expected values are independent
hand-ledger facts rather than values regenerated by the implementation.

## Measure it

```bash
cmake --build build/ch17 --target ch17_backtest_benchmark -j
ctest --test-dir build/ch17 -R ch17_backtest_benchmark --output-on-failure
```

The benchmark executes 200,000 in-memory events after two warmups and prints 11
raw microsecond samples, their median and IQR. Its validator first requires one
fill, final equity 10100, and checksum 131300. A credible report must also record
CPU, compiler, Release flags and system load; the timings are observations, not
portable promises.

## Failure that shaped the boundary

The portfolio stores positions by symbol, but the final snapshot accepts only
one mark price. An early multi-symbol path could therefore produce a plausible
but financially invalid total equity. The project now rejects mixed-symbol input
with exit status 2 until a complete timestamp-consistent price map and missing-
price policy are designed. `failures/mixed_symbols.cpp` preserves the experiment,
and CTest checks the stable diagnostic category.

## Deliberate limits

- one symbol and one cash currency per run;
- cash-account policy with no borrowing, margin, leverage, or short selling;
- synchronous immediate full fills;
- fixed fee and deterministic slippage only;
- no calendar, corporate actions, borrowing, margin, risk service or exchange;
- no claim that the sample strategy is profitable or production-ready;
- benchmark excludes CSV, disk, Python calls and concurrent queues.

These limits are part of the evidence. Extending the project safely means adding
one behavior tracer bullet at a time without weakening the existing seams.
