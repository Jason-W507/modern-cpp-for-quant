\section{交付：把循环中的计算拆成多文件工具}

第 2 章的行情筛选器把读取、计算和输出全部写在 \texttt{main} 中。程序继续增长时，重复的名义金额公式很容易在不同分支产生不同版本，也无法单独说明哪些函数只读取数据、哪些函数会修改累计状态。本章把计算拆成一个真实的多文件工具：入口从标准输入读取任意多行“价格 数量”，实现文件负责累计总名义金额和总数量，最后输出成交量加权平均价（VWAP）。

给定：

\begin{lstlisting}[numbers=none]
100.00 10
101.00 20
99.00 10
\end{lstlisting}

必须逐字符得到：

\begin{lstlisting}[numbers=none]
notional=4010.00 quantity=40 vwap=100.25
\end{lstlisting}

这组结果可独立手算：总数量为 $10+20+10=40$，总名义金额为 $100\times10+101\times20+99\times10=4010$，所以 VWAP 为 $4010/40=100.25$。完成判据还包括：项目能从全新构建目录配置；参数实验能预测调用者是否改变；三个故障实验能按编译诊断或链接诊断分类。

\section{从表达式到函数}

\subsection{场景：同一公式需要一个名字和边界}

若每次累计都直接写 \texttt{price * quantity}，公式的含义、输入和结果只能靠上下文猜。函数把一段计算命名，并建立局部作用域。最小规则可以读作：

\begin{lstlisting}
return_type function_name(parameter_declarations);
\end{lstlisting}

这一行是\emph{声明}：分号表示这里只有函数接口，没有函数体。调用点只要先看见声明，就能检查实参数量与类型。\emph{定义}重复相同的返回类型、名称和参数列表，随后用花括号给出函数体；定义末尾不再加分号。调用写作函数名、圆括号和实参，例如 \texttt{trade\_notional(price, quantity)}。

\subsection{重构路线：一次只移动一个边界}

重构从第 2 章循环内的 \texttt{total\_notional += price * quantity;} 开始，而不是直接重写最终项目。第一步把清单 3.2 的 \texttt{trade\_notional} 定义放在单文件 \texttt{main} 之前，只把右侧表达式替换为函数调用，输出必须不变。第二步把声明放在 \texttt{main} 前、把同一定义移到 \texttt{main} 后，证明调用点只需先看见声明。第三步才把声明移入清单 3.1 的头文件、定义移入实现文件；最后让 CMake 同时编译入口和实现。每一步都用章首输入复跑，任何输出变化都说明移动边界时顺带改变了行为。

\section{按值、引用与可空指针}

\subsection{场景：函数是否可以改动调用者}

接口不仅说明“接收一个 \texttt{double}”，还要说明函数获得独立副本还是借用调用者对象。下面的完整实验由 CTest 逐字符检查：

\lstinputlisting[caption={四种参数模式的可观察差异}]{code/ch03/parameter_modes.cpp}

\texttt{double price} 是按值参数。\texttt{add\_tick} 修改自己的参数对象并返回 101，但调用者的 \texttt{original} 仍为 100。对基础数值类型，按值通常最直接。

\texttt{const double\& price} 是只读左值引用。\texttt{\&} 表示参数引用调用者已有对象，不创建独立的业务值；前面的 \texttt{const} 禁止函数通过该名称赋值。\texttt{observe\_price} 因而能读取 \texttt{original}，却不能写 \texttt{price += 1.0;}。对一个 \texttt{double}，只读引用通常没有性能优势；这里用小类型把语义显示清楚，后续较大的标准库和领域对象才更常用 \texttt{const T\&}。

\texttt{double\& cash} 是可变左值引用。\texttt{charge\_fee} 对 \texttt{cash} 的赋值直接改变调用者对象，所以输出为 995。可变引用适合“函数职责就是修改这个对象”的接口；若函数主要产生一个新值，返回值通常更易组合和测试。调用语法不会额外显示 \texttt{\&}，因此名称和文档应让副作用容易发现。

\texttt{const double original\{100.0\};} 还演示只读对象：初始化之后不能再赋值。\texttt{const} 约束的是通过该名称允许的操作，不表示数值被放到某种神秘的永久存储中。

\paragraph{与 Python 对照。}
Python 的实参传递不能概括为“所有东西按引用”：参数名称绑定到同一对象，但对名称重新赋值不会改调用者，而修改共享的可变对象可能会。C++ 把三种意图写进函数签名：按值得到独立对象，\texttt{const\&} 只读借用，\texttt{\&} 可变借用。二者不能只靠表面调用语法互相类推。

失败诊断：把字面量 \texttt{100.0} 传给 \texttt{double\&} 会在编译阶段失败，因为可变左值引用需要一个可修改、寿命明确的调用者对象；改成 \texttt{double cash\{100.0\}; charge\_fee(cash, 5.0);}。若只读函数意外要求可变引用，\texttt{const} 对象也无法调用它；正确修复是收窄函数权限为 \texttt{const double\&} 或按值，而不是删除调用者的 \texttt{const}。

\subsection{指针：允许“没有观察对象”}

引用必须绑定对象且不能改绑；指针对象保存地址，也可以保存空指针值。清单 3.3 中的三行摘录为：

\begin{lstlisting}
const double* price_view{&original};
const double pointed{*price_view};
const double* missing{nullptr};
\end{lstlisting}

第一行用取地址运算符 \texttt{\&} 得到 \texttt{original} 的地址；类型中的 \texttt{*} 声明“指向只读 \texttt{double} 的指针”。第二行的 \texttt{*price\_view} 解引用地址并读取 100。相同符号依上下文承担声明符或运算符职责，不能只按字符背诵。

\texttt{const double* missing\{nullptr\};} 明确表示当前没有对象；程序用 \texttt{missing == nullptr} 得到 1。指针可以为空，所以每次解引用前都必须由接口契约或条件证明非空。这里的裸指针只是非拥有观察，不负责销毁对象；\texttt{price\_view} 也不能比 \texttt{original} 活得更久。所有权与数组指针在第 6 章继续展开。

\paragraph{与 Python 对照。}
Python 常用 \texttt{None} 表示没有对象；C++ 裸指针用 \texttt{nullptr} 表示没有地址。但 Python 名称会自动保持对象引用，非拥有 C++ 指针不会延长被观察对象的生命周期。引用适合必有对象，指针适合“可能没有”的观察接口。

失败诊断：直接计算 \texttt{*missing} 是未定义行为，不能把某次崩溃当成契约；修复是在解引用前检查非空，并让被指向对象覆盖整个使用期。

\section{重载：同名操作的不同参数表}

同一领域动作有时存在不同的输入形式。本章头文件声明了两个 \texttt{trade\_notional}：第一个接收价格和数量；第二个额外接收乘数。它们名称相同，参数数量不同，这叫函数重载。调用 \texttt{trade\_notional(price, quantity)} 只有两个实参，编译器选择二参数候选；三实参调用选择另一个定义。三参数版本复用二参数版本，再乘以 multiplier，避免复制基础公式。

重载的签名必须在参数数量或参数类型上可区分；只改变返回类型不够，因为调用点不能总从接收结果的上下文唯一决定候选。默认实参也可能让两个候选同时可用，从而产生“调用有歧义”类别的编译错误。本书优先让重载表达同一概念；完全不同的业务动作应使用不同名称。

\paragraph{与 Python 对照。}
Python 后定义的同名函数通常替换前一个绑定，常用默认参数或 \texttt{*args} 手工分派。C++ 会在编译期建立同名候选集，根据实参数量、类型和所需转换选择唯一最佳匹配；没有可行候选或最佳候选不唯一都会编译失败。

失败诊断：新增 \texttt{double trade\_notional(double price, int quantity, double multiplier = 1.0);} 后，二实参调用可能同时匹配原二参数版本和带默认实参的版本。根因是接口集合有歧义；修复为移除默认值、移除重复能力，或使用含义不同的名称。

\section{头文件、实现文件与翻译单元}

\subsection{场景：让不同源文件共享同一接口}

每个 \texttt{.cpp} 会先经过预处理，再独立编译成一个翻译单元的目标文件。入口 \path{main.cpp} 需要看见函数声明，实现文件 \path{market_math.cpp} 负责给出定义。最后，链接器把两个目标文件组合成程序。头文件用于共享声明，本身不会“自动参与构建”。

\texttt{\#include "quant/ch03/market\_math.hpp"} 使用双引号查找项目头文件；标准库头文件继续使用尖括号。预处理器把头文件内容带入当前翻译单元。头文件可能经不同路径被重复包含，因此清单使用 include guard：\texttt{\#ifndef} 检查宏尚未定义，\texttt{\#define} 建立标记，末尾 \texttt{\#endif} 关闭条件区域。同一翻译单元第二次读到它时，声明区域会被跳过。

\texttt{namespace quant::chapter3 \{ ... \}} 把名称放进项目自己的命名空间，降低与其他库同名函数冲突的风险。调用点写全限定名 \texttt{quant::chapter3::add\_trade}；头文件不写 \texttt{using namespace}，避免把选择强加给每个包含者。

\paragraph{与 Python 对照。}
Python 的 \texttt{import} 通常加载模块对象并在运行时绑定名称；C++ 的 \texttt{\#include} 是预处理期文本包含，每个 \texttt{.cpp} 仍独立编译。头文件提供共同声明，定义则必须在最终链接中恰好满足需要。把 include guard 理解成模块加载缓存会得到错误心智模型。

失败诊断：若编译器报告找不到头文件，先检查 include 拼写和目标的 include 目录；若只有 \texttt{main.cpp} 进入目标，编译能通过但链接器会找不到 \texttt{market\_math.cpp} 中的定义。修复方式是让正确实现文件参与同一目标；直接把 \texttt{.cpp} include 进入入口文件会混淆翻译单元边界。

\section{三个诊断实验：定义数量与对象寿命}

故意失败文件位于 \path{code/ch03/failures/}，不进入默认绿色目标。测试只匹配稳定诊断类别，不绑定完整英文文本。

\subsection{缺失定义}

\path{missing_definition.cpp} 声明并调用 \texttt{fee\_rate}，却没有函数体。源文件能编译成目标文件，链接时报告 \texttt{undefined reference} 或 \texttt{unresolved external symbol} 类别。根因是最终链接集合缺少定义；“头文件没被执行”并不符合这里的执行模型。修复是提供签名一致的唯一定义并让对应目标文件参与链接。

\subsection{重复定义}

\path{duplicate_definition_a.cpp} 与 \path{duplicate_definition_b.cpp} 各自都能编译，却都定义了同一个 \texttt{fee\_rate()}。把两个目标文件一起链接时应报告 \texttt{multiple definition} 或 \texttt{already defined} 类别。这是“一份声明可以被许多翻译单元看见，但非内联普通函数在程序中需要一个定义”的直接证据。修复是把声明留在头文件、定义只留在一个实现文件。

\subsection{悬空引用}

\path{dangling_reference.cpp} 返回局部 \texttt{double} 对象的引用。局部对象在函数返回时已经结束生命周期，调用者拿到的引用随即悬空。高警告级别编译应报告“返回局部对象引用”类别；本实验不运行生成的程序，因为读取悬空引用是未定义行为，不能把某次崩溃或数值当成稳定结果。修复是按值返回这个小对象，或引用一个已证明比调用者活得更久的对象。

\section{本章小结}

函数声明让调用点在编译期检查接口，定义提供唯一实现，调用创建参数对象并取得返回结果。按值表达独立副本，\texttt{const\&} 表达只读借用，\texttt{\&} 表达可变借用，指针还可用 \texttt{nullptr} 表示没有观察对象；重载让同名动作拥有可区分的参数表。头文件共享声明，include guard 控制重复包含，命名空间管理名称，多个 \texttt{.cpp} 分别编译后由链接器组合。诊断时先问每个翻译单元是否编译，再问程序是否拥有所需且唯一的定义，最后确认引用或指针仍指向存活对象。
