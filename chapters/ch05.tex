\section{从公开记录认识 struct 与 enum class}

\subsection{场景：先把同一行字段放进一个对象}

第 4 章用三个等长 \texttt{vector} 保存代码、价格和数量，同一索引共同代表一行。只要漏改一列，表示就会分裂。\texttt{struct} 可以把相关字段组合成一个记录，\texttt{vector<QuoteRecord>} 的每个元素便是一整行。

\lstinputlisting[caption={公开聚合记录与作用域枚举}]{code/ch05/records.cpp}

\texttt{struct QuoteRecord \{ ... \};} 定义一个新类型。类型定义的右花括号后必须有分号；花括号内部三个声明各自也以分号结束。\texttt{struct} 成员默认是公开的，因此 \texttt{quote.symbol} 用点号直接访问成员。\texttt{QuoteRecord quote\{"AAPL", 100.0, 10\};} 按声明顺序聚合初始化三个字段。

\texttt{enum class Trend \{ down, flat, up \};} 定义三个互斥的命名值。\texttt{enum class} 不把 \texttt{up} 泄漏到外层作用域，使用时必须写 \texttt{Trend::up}；它也不会静默当作整数参与计算。\texttt{switch} 对枚举值分派，每个 \texttt{case} 后有冒号。本例在每个分支直接 \texttt{return}，因此不需要 \texttt{break}；若只执行语句而不离开，忘记 \texttt{break} 会继续贯穿下一标签。

该程序故意把公开价格改成 \(-1\)，并稳定输出 \texttt{price=-1}。这不是未定义行为，而是一个设计缺口的证据：语法上有效的赋值制造了业务上无效的行情。

\begin{pythonbridge}
Python 的 \texttt{dataclass} 与 C++ 聚合都适合透明记录，但 Python 属性可在运行期重新绑定为不同类型；C++ 字段类型在编译期固定。两者的公开字段都不能自行阻止 \texttt{price=-1}，需要在创建或更新边界加入不变量。
\end{pythonbridge}

失败诊断：把 \texttt{Trend::up} 写成裸 \texttt{up} 会在编译期得到“名称未声明”一类诊断。根因是作用域枚举要求限定名；修复是恢复 \texttt{Trend::up}，不要退回可与整数混用的旧式枚举。

立即练习：把 \texttt{Trend::up} 改为 \texttt{Trend::down}，先预测末尾精确输出为 \texttt{trend=down}，再运行验证。只改变枚举值，不修改字符串转换函数。

\section{class 把有效状态写进构造边界}

\subsection{场景：行情一旦存在就必须可统计}

若每个调用者都要记住“代码非空、价格有限且为正、数量为正”，检查迟早会遗漏。\texttt{MarketQuote} 把字段设为私有，只允许构造函数创建对象，并通过只读成员函数观察值。

\lstinputlisting[caption={有效行情与被拒绝行情}]{code/ch05/class_invariants.cpp}

\texttt{class} 的成员默认私有。类声明中的 \texttt{public:} 与 \texttt{private:} 是访问标签，冒号后直到下一个标签的声明共享该权限。构造函数与类同名、没有返回类型；\texttt{MarketQuote(std::string symbol, double price, int quantity)} 在函数体运行前通过成员初始化列表建立字段。

接口中的 \texttt{double price() const;} 末尾 \texttt{const} 修饰成员函数，承诺调用不会修改该对象的非 \texttt{mutable} 状态。因此 \texttt{const MarketQuote valid} 仍可调用 \texttt{price()}。返回代码时使用 \texttt{const std::string\&}，让调用者只读借用类所拥有的字符串；借用不能比对象活得更久。

构造函数发现非法字段就执行 \texttt{throw std::invalid\_argument\{...\}}。对象没有构造成功，调用点跳到匹配的 \texttt{catch (const std::exception\& error)}；作用域中已经构造完成的自动对象会在传播过程中销毁，这称为栈展开。捕获后读取 \texttt{error.what()} 得到原因，但只在命令行边界记录一次。

\begin{pythonbridge}
Python 的 \texttt{\_\_init\_\_} 也可抛出 \texttt{ValueError} 阻止对象交付；C++ 的关键差异是成员初始化早于构造函数体，且栈展开会确定性销毁已经完成构造的自动对象。第 6 章会把这一机制用于文件和动态资源的 RAII。
\end{pythonbridge}

故意失败的 \path{code/ch05/failures/private_access.cpp} 尝试读取 \texttt{quote.quantity\_}。它不进入绿色目标；编译必须非零退出，并匹配 private 或 inaccessible 诊断类别。根因是调用者越过公开接口，修复是调用 \texttt{quantity()}，而不是把字段改回 \texttt{public}。

立即练习：把有效对象的数量从 10 改为 0。预期程序进入 \texttt{catch} 并得到 \texttt{quantity must be positive}；随后恢复 10，解释为何不需要在每次统计前重复检查数量。

\section{成员函数维护分析器不变量}

\subsection{场景：只统计一个代码且至少有一行}

分析器把目标代码、价格序列和总数量放在同一对象中。完整声明如下，\texttt{MarketSummary} 只是计算完成后的公开快照，\texttt{MarketAnalyzer} 则维护可变状态：

\lstinputlisting[caption={行情值、摘要记录与分析器接口}]{code/ch05/include/quant/ch05/market.hpp}

构造函数先拒绝空的目标代码。\texttt{add} 只接收代码相同的 \texttt{MarketQuote}；不匹配时抛出 \texttt{symbol does not match analyzer}，所以数量和价格序列永远描述同一标的。

成员函数内可直接写成员名，也可写 \texttt{this->prices\_}。\texttt{this} 是指向当前对象的指针，箭头先通过指针找到对象再访问成员。本章实现用 \texttt{this->} 明确指出 \texttt{add} 修改的是当前分析器；没有名称歧义时省略它通常更简洁。

\texttt{summary() const} 不修改分析器。它先拒绝空价格序列，再用首末价计算简单收益率
\[
100\left(\frac{P_{last}}{P_{first}}-1\right),
\]
并用 \texttt{minmax\_element} 得到区间。价格已由 \texttt{MarketQuote} 保证为正，因此分母不会为零。末价大于、等于或小于首价时分别产生 \texttt{Trend::up}、\texttt{flat} 或 \texttt{down}。

\begin{pythonbridge}
Python 方法显式写 \texttt{self} 参数；C++ 非静态成员函数隐式获得 \texttt{this}。Python 常在实例字典中加入字段，C++ 的私有成员集合属于类型定义，调用者只能通过编译期已声明的公开成员函数操作它。
\end{pythonbridge}

失败诊断：查询数据中不存在的 TSLA 时，旧实现对空 \texttt{vector} 调用 \texttt{front()}，WSL 中曾以状态 \(-11\) 崩溃。根因是成员函数没有先证明“至少一行”的前置条件。当前实现抛出 \texttt{no rows for symbol TSLA}，入口捕获后返回 2。

立即练习：把正常数据第二条 AAPL 价格从 101 改为 99。预期 \texttt{return=-1.00\%}、\texttt{low=99.00}、\texttt{high=100.00}、\texttt{trend=down}；行数和总数量不变。

\section{多文件 CLI 与异常边界}

\subsection{场景：领域错误必须带回 CSV 行号}

\path{csv_reader.hpp} 只暴露 \texttt{read\_market\_csv(std::istream\&)}。实现逐行切分，把文本转换为数值，再调用 \texttt{MarketQuote} 构造函数；若构造拒绝字段，读取层补上 \texttt{line N:} 后重新抛出。这样类不依赖 CSV，CSV 又不复制类的不变量。

\lstinputlisting[caption={在程序边界捕获一次并输出摘要}]{code/ch05/src/main.cpp}

\texttt{try \{ ... \}} 包围可能失败的读取、构造和统计；\texttt{catch} 位于入口边界，只负责把异常转换为 \texttt{error=原因} 与状态 2。正常路径写 \texttt{cout}，诊断路径写 \texttt{cerr}，测试同时断言另一个流为空。不能写空的 \texttt{catch (...)} 后继续统计，否则错误上下文与半份数据都会被隐藏。

固定测试覆盖以下行为：正常 AAPL 摘要；空代码、非法价格和非正数量；错误表头、列数、价格文本与数量文本；不存在的目标代码；usage 与文件打开失败。完整读取和分析实现位于 \path{code/ch05/src/}，并在附录 C 原样给出。

\begin{pythonbridge}
Python 常在命令行入口捕获 \texttt{Exception} 并转换退出码；C++ 同样应在有能力决定协议的边界捕获。不要在每一层重复记录，也不要把文件打不开、CSV 语法错误和对象不变量错误都改写成同一句“分析失败”。
\end{pythonbridge}

失败诊断：价格文本 \texttt{not-a-price} 最初泄漏了标准库实现消息 \texttt{stod}。这不是稳定领域契约。修复是在 CSV 层完整消费文本并固定为 \texttt{invalid number: price}，再附加行号。

立即练习：把正常文件的第 2 行数量改为 \texttt{ten}。预期 stdout 为空、stderr 为 \texttt{error=line 2: invalid number: quantity}、退出状态为 2；恢复后输出任务必须重新逐字匹配。

\section{自测、编码任务与面试表达}

\begin{enumerate}
  \item \texttt{struct} 与 \texttt{class} 的默认访问权限有何区别？二者是否代表不同对象模型？
  \item 为什么使用 \texttt{Trend::up} 而不是裸 \texttt{up}？\texttt{switch} 分支何时需要 \texttt{break}？
  \item 构造函数为何没有返回类型？成员初始化列表在函数体之前做什么？
  \item 尾随 \texttt{const} 修饰谁？它与返回 \texttt{const std::string\&} 分别约束什么？
  \item \texttt{this} 指向什么？点号与箭头访问成员的对象来源有何不同？
  \item 为什么 \texttt{MarketQuote} 适合构造失败，而 \texttt{MarketSummary} 适合公开字段？
  \item 异常传播时哪些对象会被销毁？为什么只在 CLI 边界记录一次？
  \item 私有成员编译失败与非法价格运行期失败分别属于哪个阶段？如何恢复？
\end{enumerate}

编码任务：使用现有 \texttt{MarketAnalyzer} 构造两条 AAPL 行情，输出最高价与最低价之差以及趋势。可运行答案位于 \path{code/ch05/exercises/price_range_solution.cpp}，精确输出必须为 \texttt{symbol=AAPL range=1.00 trend=up}。

\begin{interviewcheck}
“为什么不把字段全部设为 public？”回答应包含：公开记录适用于无需维护跨字段不变量的结果；输入对象由构造函数保证有效；私有表示允许未来替换存储；测试通过公开行为而不是读取内部成员。随后用负价格、空分析器崩溃和带行号诊断作为证据。
\end{interviewcheck}

\section{本章小结}

\texttt{struct} 适合透明记录，\texttt{enum class} 提供有作用域的有限状态；\texttt{class} 通过构造函数、访问控制和成员函数守住不变量。基础篇行情分析器已经能从干净目录读取 CSV、拒绝坏数据并输出可验证摘要。下一章从这些对象出发学习生命周期、复制移动、RAII 与所有权。
