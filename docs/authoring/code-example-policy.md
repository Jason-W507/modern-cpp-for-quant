# 代码清单、失败实验与项目快照约定

这些约定让 PDF 中的代码能够被编译证据约束，同时避免用空目录或不可运行草图制造完成度。

## 完整代码清单

<!-- contract:complete-listing -->

- 能单独构成程序、函数或类型定义并被读者复制的清单，必须来自真实源码，而不是在 TeX 中维护第二份副本。
- 章节源码按稳定章节编号组织；CMake target 使用 `chNN_用途` 命名，章节改标题时不重命名稳定编号。
- 每个完整程序至少有一个构建目标；有确定输出时再增加 CTest 行为检查。
- 只用于解释一个声明或表达式的短片段可以内联，但必须明确省略上下文，不能伪装成可直接编译的程序。

## 故意失败示例

<!-- contract:intentional-failure -->

- 故意失败示例与绿色源码隔离，不能被默认 `all` 目标编译。
- 每个失败实验记录触发命令、失败阶段、稳定诊断类别、根因和恢复步骤。
- 编译器完整错误文本不是跨版本契约；验收“链接器找不到定义”“AddressSanitizer 报告越界”等类别与非零退出状态。
- 运行 UB 示例前必须说明隔离方式，不能把未定义输出写成预期值。

## 章节项目快照

<!-- contract:chapter-snapshot -->

- 只在项目行为达到一个可演示里程碑时创建快照，不提前建立 18 个空目录。
- 快照名称包含稳定章节编号和行为名称；每个快照能够从自身入口配置、构建和运行。
- 快照固定该章教学状态，最终项目继续演进；二者共享测试预期或数据口径，但不通过隐式引用后续源码来假装独立。
- 有意保留的重复必须服务于离线复现，避免复制与该阶段无关的文件。

## 自动验证

<!-- contract:automation -->

- `python tools/check_book_contract.py` 验证 18 章职责、语法矩阵和本约定的结构标记。
- 同一命令读取章节学习单元状态与代码证据登记；章节只有在正文、示例、失败实验、输出任务、自测和反馈证据齐全时才能标记为 `accepted`。
- TeX 中的每个完整外部清单必须登记真实源码和 CMake target；新增故意失败或项目快照时必须登记诊断类别或独立构建入口。
- `book-manifest.json` 的 `code_evidence` 中，完整清单项使用 `tex`、`source`、`target`；故意失败项使用 `source`、`stage`、`diagnostic_category`；项目快照项使用 `path`、`entry_target`。
- CMake/CTest 验证完整 C++ 清单、项目行为 seam 与书籍契约命令。
- LaTeX 验证独立于 C++ 构建；整书发布 ticket 同时运行两条链路。
- 新增完整清单、失败实验或快照时，在同一个 ticket 内补上相应验证入口。

## 命名与稳定性

<!-- contract:naming -->

- `chNN` 是章节代码的稳定机器标识，中文标题是面向读者的可编辑名称。
- 测试名称描述公开行为 seam，不描述私有函数或内部调用次数。
- 输出文件名保持稳定；临时构建、失败日志与渲染中间文件不作为教材资产提交。
