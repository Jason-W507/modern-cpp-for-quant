# 章节学习单元验收清单

本清单验收“目标读者能否独立完成一章”，而不是验收 `.tex` 文件是否存在。第 1--10 章以概念学习闭环为主；第 11--17 章按主题选择证据结构；第 18 章负责汇总求职表达。所有章节仍需提供可观察输出、真实代码证据和学习反馈。

## 状态登记

`book-manifest.json` 是写作契约的唯一结构化事实源，直接保存章节/附录验收与代码证据，同时声明语法矩阵、清单、主文件和成品 PDF 的路径。仓库不再保留重复的章节、附录或代码证据 JSON；页数仅由发布检查从成品动态读取。`planned` 表示尚未开始，`draft` 表示允许证据不完整，`accepted` 则必须同时登记：正文路径、至少一个可运行示例、失败实验源码与诊断类别、具体输出任务、自测数量、反馈答案路径，以及本清单全部 contract markers。验证命令从这一个入口读取结构化数据并检查字段，缺少任一项都不能成为 `accepted`。

PRD 明确指定的校准章允许在作者实施顺序中先于其最终先修章节验收，但必须在 `book-manifest.json` 的 `chapter_units` 中登记 `calibration-contract`、列出最终顺序中的先修章节，并以冻结的语法矩阵检查没有越出这些先修知识。这个例外只解决写作校准的依赖环，不改变读者顺序，也不允许正文把先修语法当作本章新授内容；列出的先修章节完成后必须回归复验校准章。除 PRD 点名的校准章外，`accepted` 仍要求更早章节已经教学并练习全部先修概念。

## 1. 入口与输出

<!-- contract:prerequisites -->

- [ ] 先修知识只引用更早章节已经教学并练习过的概念；PRD 点名的校准章则登记并遵守最终顺序的先修契约。
- [ ] 开篇说明本章解决的量化工作或求职问题。

<!-- contract:learning-output -->

- [ ] 读者输出任务给出可观察结果、运行命令或行为断言。
- [ ] 完成判据不使用“理解”“熟悉”等无法验证的单独表述。

## 2. 与主题匹配的教学闭环

第 1--10 章在首次教授语言概念时采用“场景—规则—可运行示例—解释—Python 边界—失败诊断—立即练习”。七项可以跨相邻小节自然展开，验收单位是完整概念，而非机械要求每个小节重复七个标题。

第 11--17 章不再套用统一七步模板。工程主题可按“问题—设计—证据—限制”组织；性能主题可按“假设—实验协议—原始数据—结论—威胁”组织；并发主题可按“状态—所有者—同步边—停止协议—故障实验”组织。验收关注这些证据是否闭合，而非标题次序。

<!-- contract:scenario -->

- [ ] 基础概念的问题场景说明为什么现在需要它；后半部说明工程问题或实验假设。

<!-- contract:syntax-rule -->

- [ ] 新语法或规则解释标点、类型、前置条件和结果；后半部设计说明写清不变量与边界。

<!-- contract:runnable-example -->

- [ ] 示例或实验完整、可运行，并来自参与构建的真实源码。

<!-- contract:guided-explanation -->

- [ ] 基础概念逐步解释关键行、求值顺序、对象变化或控制流；进阶主题解释证据如何支持结论。

<!-- contract:python-boundary -->

- [ ] 出现真实迁移冲突时，Python 对照同时写出相似处和不等价边界；没有冲突时不为模板完整而硬加。

<!-- contract:failure-diagnosis -->

- [ ] 失败实验或威胁分析说明触发方法、可观察结果、根因和恢复方式。

<!-- contract:immediate-practice -->

- [ ] 基础概念的立即练习只改变一个核心条件；进阶主题可用章末复现、修改或开放任务，并给出可检查结果。

## 3. 代码证据

<!-- contract:code-evidence -->

- [ ] 完整清单由真实源码引入，默认 C++20 构建能够编译。
- [ ] 故意错误不进入绿色构建，并以稳定诊断类别而不是整段编译器文本验收。
- [ ] 示例输出来自测试中的独立已知值，不由同一实现重新计算预期值。
- [ ] 使用平台相关命令时，正文主线为 Linux/WSL；Windows 只补差异。

## 4. 学习反馈

<!-- contract:feedback -->

- [ ] 章末自测覆盖“定义—使用时机—代价—失败例子”。
- [ ] 基础篇全部编码练习有可运行答案；进阶核心题有完整答案。
- [ ] 非完整答案至少给出提示、验收标准和常见错误。
- [ ] 答案引用的源码、命令和输出与正文版本一致。

## 5. 项目与连贯性

<!-- contract:project-connection -->

- [ ] 适用时把小例子中的同一概念应用到行情分析器或回测引擎。
- [ ] 关键项目阶段有独立可构建快照，后续重构不破坏早期教学状态。
- [ ] 术语、数据口径和错误语义与 `CONTEXT.md`、ADR 及前章一致。
- [ ] 本章没有超出语法矩阵中更早章节已教学的概念；校准章按其登记的最终顺序先修章节判断。

## 6. 出版质量

<!-- contract:publication -->

- [ ] 章节页数落在书籍契约预算附近；偏离时通过内容价值解释，而不是灌水或删掉必要教学。
- [ ] LaTeX 构建无未定义引用、缺失字形、致命错误或影响阅读的溢出。
- [ ] 代码、表格、提示框与分页经过渲染抽查。
- [ ] 章节通过后才勾选对应 ticket 的验收项。
