# 章节学习单元验收清单

本清单验收“目标读者能否独立完成一章”，而不是验收 `.tex` 文件是否存在。基础篇必须逐项满足；进阶篇只有在确实不适用时才能写明理由。

## 状态登记

`chapter-units.json` 是章节学习单元的公开验收 seam。`planned` 表示尚未开始，`draft` 表示允许证据不完整，`accepted` 则必须同时登记：正文路径、至少一个可运行示例、失败实验源码与诊断类别、具体输出任务、自测数量、反馈答案路径，以及本清单全部 contract markers。验证命令会检查路径和字段，缺少任一项都不能成为 `accepted`。

## 1. 入口与输出

<!-- contract:prerequisites -->

- [ ] 先修知识只引用更早章节已经教学并练习过的概念。
- [ ] 开篇说明本章解决的量化工作或求职问题。

<!-- contract:learning-output -->

- [ ] 读者输出任务给出可观察结果、运行命令或行为断言。
- [ ] 完成判据不使用“理解”“熟悉”等无法验证的单独表述。

## 2. 核心小节的七步闭环

每个核心小节都应能找到以下七项；它们可以穿插呈现，但不能用章末统一补一段来冒充。

<!-- contract:scenario -->

- [ ] 问题场景说明为什么现在需要这个概念。

<!-- contract:syntax-rule -->

- [ ] 语法或规则解释标点、类型、前置条件和结果，不假设读者见过。

<!-- contract:runnable-example -->

- [ ] 最小例子完整、可运行，并来自参与构建的真实源码。

<!-- contract:guided-explanation -->

- [ ] 逐步解释关键行、求值顺序、对象变化或控制流。

<!-- contract:python-boundary -->

- [ ] Python 对照同时写出相似处和不等价边界。

<!-- contract:failure-diagnosis -->

- [ ] 失败实验说明触发方法、预期诊断类别、根因和修复，而非只警告“不要这样写”。

<!-- contract:immediate-practice -->

- [ ] 立即练习只改变一个核心条件，并给出可检查结果。

## 3. 代码证据

<!-- contract:code-evidence -->

- [ ] 完整清单由真实源码引入，默认 C++20 构建能够编译。
- [ ] 故意错误不进入绿色构建，并以稳定诊断类别而不是整段编译器文本验收。
- [ ] 示例输出来自测试中的独立已知值，不由同一实现重新计算预期值。
- [ ] 使用平台相关命令时，正文主线为 Linux/WSL；Windows 只补差异。

## 4. 学习反馈

<!-- contract:feedback -->

- [ ] 章末自测覆盖“定义—使用时机—代价—失败例子”。
- [ ] 基础篇全部编码练习有可运行答案；进阶核心题有完整答案。
- [ ] 非完整答案至少给出提示、验收标准和常见错误。
- [ ] 答案引用的源码、命令和输出与正文版本一致。

## 5. 项目与连贯性

<!-- contract:project-connection -->

- [ ] 适用时把小例子中的同一概念应用到行情分析器或回测引擎。
- [ ] 关键项目阶段有独立可构建快照，后续重构不破坏早期教学状态。
- [ ] 术语、数据口径和错误语义与 `CONTEXT.md`、ADR 及前章一致。
- [ ] 本章没有提前使用语法矩阵中尚未教学的概念。

## 6. 出版质量

<!-- contract:publication -->

- [ ] 章节页数落在书籍契约预算附近；偏离时通过内容价值解释，而不是灌水或删掉必要教学。
- [ ] LaTeX 构建无未定义引用、缺失字形、致命错误或影响阅读的溢出。
- [ ] 代码、表格、提示框与分页经过渲染抽查。
- [ ] 章节通过后才勾选对应 ticket 的验收项。
