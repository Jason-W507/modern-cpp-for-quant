# 《Python 量化人的 Modern C++》设计规格

## 1. 目标与读者

本项目基于 `D:\Latex\ElegantBook` 模板，制作一本可由 MiKTeX/XeLaTeX 编译的中文 Modern C++ 教程。读者已经能够熟练使用 Python，希望申请或胜任 Quant Developer、Research Engineer 及相近岗位。

首版定位为完整求职实战版：建立系统的 C++20 心智模型，同时产出一个可展示、可测试、可基准测试的量化工程项目。正文不重复讲解基础 Python，也不把读者已有的 Python 直觉简单映射为 C++ 语法；所有类比都必须说明两种语言在对象模型、生命周期、错误处理和性能成本上的差异。

## 2. 内容边界

主线标准为 C++20，以 Linux 上的 GCC/Clang、CMake 和 CTest 为主要工程环境。必要处加入 Windows/MSVC 差异提示，C++23 特性仅放入延伸阅读。

量化场景覆盖研究工程、数据处理、回测组件、数值性能、并发及低延迟基础。金融案例用于承载工程知识，不教授交易盈利策略，也不把本书扩展为金融理论、网络协议、无锁算法或 SIMD 专著。

全书以一个逐章演化的事件驱动回测引擎为贯穿项目。最终项目支持 CSV 行情输入、策略接口、订单与成交、组合状态、绩效统计、测试和基准测试，并解释 pybind11 接口边界；首版不依赖大型第三方量化框架。

## 3. 全书结构

### 第一部分：从 Python 迁移

1. Python 开发者的 C++ 心智切换：编译、链接、未定义行为与零成本抽象。
2. 类型、值类别与 `const`：从动态对象到静态契约。
3. RAII、智能指针与所有权：让资源生命周期可证明。
4. STL、迭代器、算法与 ranges：构建现代数据管道。

### 第二部分：写出可靠组件

5. 类、接口与值语义：设计行情、订单和成交模型。
6. 模板、concepts 与编译期编程：构建有约束的策略接口。
7. 错误处理与可观测性：异常、显式错误、日志与断言。
8. CMake、测试与代码质量：从能运行到可维护工程。

### 第三部分：量化性能工程

9. 数据布局、缓存与分配：理解真实性能来源。
10. Benchmark、profiling 与优化方法：先测量，再优化。
11. 并发、原子与任务系统：正确处理行情与计算流水线。
12. 数值计算与 Python 互操作：精度、向量化与 pybind11 边界。

### 第四部分：求职到工作

13. 贯穿项目：组装、验证并分析事件驱动回测引擎。
14. 量化 C++ 求职：代码题、系统设计、简历项目与入职检查表。

附录包括工具链速查、术语表、章末练习答案与思路、推荐阅读和 30 天学习路线。

## 4. 章节教学模板

每章固定包含以下元素：

1. 学习目标与先修知识。
2. Python 心智模型及其不等价边界。
3. C++20 核心概念与最小示例。
4. 量化工作场景中的组件或数据流。
5. 常见错误、未定义行为与诊断方法。
6. 性能和工程权衡，仅在有测量依据时给出性能结论。
7. 面试检查点。
8. 编码练习与概念练习。

练习采用章末练习、书末精炼答案或解题思路的方式。关键题提供可运行参考代码，但首版不为每道题写长篇完整题解。

## 5. 项目与文件结构

目标目录为 `D:\Latex\modern-cpp-for-quant`：

- `main.tex`：书籍入口、封面信息与全局设置。
- `elegantbook.cls`：从指定模板复制的本地类文件，保持原模板目录不变。
- `chapters/`：每章一个 TeX 文件。
- `appendices/`：答案、工具链、术语表和学习路线。
- `figures/`：原创图示与许可明确的图片。
- `code/`：按章组织、可独立构建的小例子。
- `project/`：贯穿式回测引擎，包含 `include/`、`src/`、`tests/` 与 `benchmarks/`。
- `references.bib`：参考文献。
- `docs/superpowers/specs/`：设计规格。
- `build/`：LaTeX 构建产物。

LaTeX 源文件按章节拆分，由 `main.tex` 使用 `\include` 或 `\input` 组合。代码清单尽量从真实源码文件引入，避免书中代码和可运行代码长期分叉。

## 6. 贯穿项目的数据流

数据流为：CSV 行情读取器解析并校验输入，生成规范化市场事件；事件循环将事件分发给策略；策略产生订单意图；撮合模拟器生成成交；组合模块更新持仓、现金与权益；统计模块输出收益、波动、回撤和交易摘要。

各模块通过小型、显式接口通信。数据模型优先采用值语义；只有共享生命周期确有必要时才引入智能指针。热路径上的分配、复制和同步必须可被 benchmark 或 profiler 观察。

## 7. 错误处理与正确性

- 程序员错误和内部不变量使用断言或契约式检查。
- 外部输入、CSV 解析和 I/O 失败使用显式错误返回或异常，并在边界处补充上下文。
- 热路径不使用异常表达普通控制流。
- 并发内容先建立所有权、同步和停止协议，再讨论吞吐与尾延迟。
- 浮点结果使用容差比较；金额示例明确说明浮点、定点或整数最小货币单位的取舍。

## 8. 验证策略

代码验证分四层：小例子编译检查、组件单元测试、端到端回测一致性测试、性能基准测试。性能章节不得仅凭直觉声称某实现更快。

文档使用本机 MiKTeX 的 `latexmk -xelatex` 构建至 `build/`。验收时至少检查：成功生成 PDF、无未定义引用或引用文献、无缺失字形、无致命错误，并抽查溢出版面警告和代码清单可读性。

## 9. 首版完成标准

1. 14 章及 4 个附录均有完整、连贯的教学正文，不保留占位章节。
2. 所有关键代码示例具备对应源码，并通过 C++20 编译检查。
3. 贯穿项目可配置、构建、测试并运行一个最小样例数据集。
4. 至少提供一组可重复的性能基准，正文准确解释其限制。
5. MiKTeX/XeLaTeX 能从干净构建目录生成最终 PDF。
6. 原 `D:\Latex\ElegantBook` 模板目录不被修改。

## 10. 已确认决策

- 首版深度：完整求职实战版。
- 语言标准：C++20 主线，C++23 延伸阅读。
- 工程环境：Linux GCC/Clang 为主，补充 Windows/MSVC 差异。
- 岗位侧重：研究工程兼顾。
- 练习形式：章末练习，书末答案或思路。
- 写作路线：项目主线与能力递进。
- 模板来源：`D:\Latex\ElegantBook`。
- 本机构建环境：MiKTeX，使用 XeLaTeX/latexmk 验证。

## 11. 实施约束

`D:\Latex` 当前不是 Git 仓库，因此本规格无法在现有仓库中提交。除非用户另行要求，项目创建过程不初始化 Git，也不修改模板源目录。后续实现应优先完成一份内容完整、可编译、结构可扩写的首版，而不是以空章节或大量待办项制造表面上的目录完整度。
